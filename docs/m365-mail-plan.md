# תוכנית: הזמנת משתמשים ואיפוס סיסמה במייל דרך Microsoft 365 (D86)

סטטוס: **תוכנית בלבד, לא נבנית** עד ש-IT מחבר את ה-App Registration. משתמשי בדיקה ממשיכים עם `@example.test` וסיסמה שהיוצר קובע.

## מה ה-IT צריך לעשות (פעם אחת)
1. App Registration אחד ב-Entra ID (משותף לקליטת היומן ולמייל).
2. הרשאות Application: `Calendars.Read` (קליטת זימונים) ו-`Mail.Send`.
3. הגבלת `Mail.Send` לתיבה אחת בלבד (למשל `service-app@mody.co.il`). Microsoft ממליצה היום על **RBAC for Applications ב-Exchange Online**; Application Access Policy היא השיטה הישנה ועדיין עובדת. ההחלטה בין השתיים היא של IT.
4. Client secret או certificate (עדיף certificate), עם תאריך תפוגה ובעלים לחידוש.
5. למסור לבעלים: Tenant ID, Client ID, כתובת התיבה השולחת. ה-secret נכנס ישירות ל-Vercel (Sensitive) על ידי הבעלים, לא דרך הצ'אט.

## משתני סביבה (שרת בלבד, אף פעם לא `NEXT_PUBLIC_`)
`M365_TENANT_ID`, `M365_CLIENT_ID`, `M365_CLIENT_SECRET` (או certificate), `M365_SENDER_MAILBOX`, `EMAIL_DELIVERY=graph`.

## שינויים בקוד (אחרי החיבור)
1. **מתאם מייל `graph`** לצד ה-mock הקיים: token ב-client credentials, קריאה ל-`POST /users/{sender}/sendMail`, ניסיון חוזר מוגבל, בלי לרשום את תוכן הקישור ללוגים.
2. **הזמנה (חדש):** טבלת הזמנות במיגרציה (טוקן שמור כ-hash בלבד, תוקף 24 שעות, שימוש אחד, ביטול בהזמנה חדשה). מסך "קבלת הזמנה" שבו המשתמש בוחר סיסמה ונכנס.
3. **בדיקת `@mody.co.il`** בשרת וגם ב-DB (CHECK) לחשבונות אמיתיים; `@example.test` נשאר רק לחשבונות בדיקה.
4. **"הוספת משתמש"** (יוצר ומנהל): יוצר חשבון בלי סיסמה ושולח הזמנה. "שלח הזמנה מחדש" בתפריט ⋮.
5. **"שכחתי סיסמה" (D65):** אותו מתאם; תוקף שעה, שימוש אחד; לכל חשבון פעיל.
6. **"סיסמה" של היוצר:** נשאר כגיבוי חירום בלבד (D86 (c)).
7. **Rate limits** על שליחת הזמנה ואיפוס (לפי כתובת ולפי שולח).

## נקודה טכנית שדורשת החלטה
ב-Supabase Auth תוקף הקישורים במייל (invite ו-recovery) הוא **הגדרה אחת לכל הפרויקט**. אי אפשר לתת להזמנה 24 שעות ולאיפוס שעה אחת באותה הגדרה. **ההמלצה:** טוקן הזמנה משלנו (סעיף 2), ואיפוס דרך Supabase עם תוקף שעה. החלופה, תוקף 24 שעות לשניהם, מחלישה את האיפוס.

## אישורים נדרשים לפני בנייה
המיגרציה (טבלת ההזמנות) והגדרת משתני הסביבה ב-Production דורשות אישור בעלים נפרד, כל אחת בנפרד.
