# <span dir="rtl">פרקים 1–4 — טכנאי \| שירות לקוחות \| מנהל \| יוצר</span>

<span dir="rtl">גרסת עבודה מעודכנת \| 09.11.2026 \| כוללת החלטות מאושרות ודמו להמחשה</span>

<span dir="rtl">מטרת המסמך: ריכוז תיקוני QA ושיפורי שימוש בממשקי הטכנאי, שירות הלקוחות והמנהל. המסמך מבוסס על הערות המשתמש, צילומי המסך והדמו המקורי. הוראות הפיתוח לקלוד קוד ייכתבו בשלב נפרד לאחר אישור התיקונים.</span>

# <span dir="rtl">1. הודעות סנכרון ועבודה ללא אינטרנט</span>

<span dir="rtl">במסך הבית מופיעה הודעה על פריטים שטרם הסתנכרנו עם השרת.</span>

> <span dir="rtl">• להציג הודעה פשוטה: "יש נתונים שממתינים לסנכרון עם השרת".</span>
>
> <span dir="rtl">• אם היעדר אינטרנט הוא הסיבה המאומתת, לציין: "הנתונים ממתינים לסנכרון עקב חוסר חיבור לאינטרנט".</span>
>
> <span dir="rtl">• להציג מספר פריטים ממתינים ומספר פריטים שנכשלו, ולאפשר לחיצה על "סנכרן עכשיו".</span>
>
> <span dir="rtl">• להעלים את ההודעה לאחר שכל הפריטים סונכרנו; אין לייחס כל שגיאה לחוסר קליטה.</span>

# <span dir="rtl">2. עדכון מסך הבית לאחר סיום ביקור</span>

<span dir="rtl">תקלה שאומתה: לאחר סיום הביקור של משפחת לוי בסטטוס "טופל", הביקור נשאר מוצג כפעיל ומונה "הושלמו" נשאר על 0.</span>

> <span dir="rtl">• עם סיום מוצלח בסטטוס "טופל" או "המשך טיפול", להעביר את הביקור לרשימת "הושלמו היום".</span>
>
> <span dir="rtl">• לעדכן את המונה של הביקורים שהושלמו ואת כמות הביקורים שנותרו לביצוע.</span>
>
> <span dir="rtl">• להציג בכרטיס "הביקור הבא" את הביקור הפעיל הבא לפי סדר הזמנים; כשאין ביקורים — להציג הודעה מתאימה.</span>
>
> <span dir="rtl">• ביקור שנדרש בו המשך טיפול נחשב ביקור שהושלם, אך קריאת השירות עצמה נשארת פתוחה להמשך.</span>

# <span dir="rtl">3. הצגת סטטוסים ביומן הטכנאי</span>

<span dir="rtl">להבטיח שהיומן מציג את מצב הביקור הנוכחי, בכל התצוגות.</span>

> <span dir="rtl">• לציין בכל כרטיס ביקור את שם הסטטוס באופן מילולי, לצד צבע ייעודי.</span>
>
> <span dir="rtl">• הסטטוסים: שובצה, בדרך, בטיפול, טופל, המשך טיפול.</span>
>
> <span dir="rtl">• לעדכן את הצבע והטקסט בתצוגה היומית, השבועית והחודשית מיד לאחר שינוי מצב.</span>
>
> <span dir="rtl">• ביקורים שהושלמו או נדרשים להמשך טיפול יישארו זמינים בהיסטוריית היומן.</span>

# <span dir="rtl">4. שליחת הודעות מייל בסיום ביקור</span>

<span dir="rtl">לאחר חיבור Microsoft 365, יש לשלוח הודעה אוטומטית בסיום כל ביקור.</span>

> <span dir="rtl">• נמענים: שיראל — מנהלת השירות הטכני; רותם — המנהל של שיראל.</span>
>
> <span dir="rtl">• לשלוח הודעה עבור סיום בסטטוס "טופל" ועבור "המשך טיפול".</span>
>
> <span dir="rtl">• לכלול מספר פנייה, לקוח, פרטי ביקור, טכנאי, סטטוס, תוצאה וסיכום טיפול; בהמשך טיפול גם סיבה ופעולות המשך שתועדו.</span>
>
> <span dir="rtl">• כתובות המייל יוגדרו לאחר אישור החיבור; להימנע ממשלוח הודעות כפולות על אותו אירוע.</span>

# <span dir="rtl">5. בדיקת האייקון ליד שמות הלקוחות</span>

<span dir="rtl">בצילומי המסך מופיע אייקון קטן המזכיר עיפרון ליד לקוחות וביקורים.</span>

> <span dir="rtl">• לברר את משמעות האייקון ואת תפקידו.</span>
>
> <span dir="rtl">• אם אין לו תפקיד ברור — להסיר אותו; אחרת להציג סמל מוסבר ועקבי.</span>

# <span dir="rtl">6. שינוי סדר הרכיבים במסך הבית</span>

<span dir="rtl">אזור "מה לאסוף לפני יציאה".</span>

> <span dir="rtl">• האזור יוצג רק כאשר קיימים פריטים לאיסוף. כשאין פריטים לאיסוף, הוא לא יוצג כלל.</span>

# <span dir="rtl">7. סנכרון נתונים בין הממשקים</span>

<span dir="rtl">שינויי סטטוס ותיעוד ביקור צריכים להשתקף בכל מסכי האפליקציה הרלוונטיים.</span>

> <span dir="rtl">• לסנכרן את מסך הבית, יומן הטכנאי וכרטיס הקריאה.</span>
>
> <span dir="rtl">• לשקף את השינוי גם ביומן המנהל ושירות הלקוחות ובמדדי הדשבורד.</span>
>
> <span dir="rtl">• להציג סיכום, תמונות, הקלטות וחתימה בהתאם להרשאות ולשמור את כל היסטוריית הביקורים.</span>
>
> <span dir="rtl">• לקשר ביקור המשך לקריאה המקורית, ללא יצירת קריאה כפולה.</span>
>
> <span dir="rtl">• עדכון המצב באפליקציה אינו מהווה אישור לשינוי אוטומטי בפגישת Outlook.</span>

# <span dir="rtl">8. השלמת תהליך סיום הביקור</span>

<span dir="rtl">יש להבטיח שמירה תקינה ותוצאה ברורה למשתמש.</span>

> <span dir="rtl">• לאפשר סיום רק לאחר מילוי שדות החובה, ולהציג בבירור מה חסר.</span>
>
> <span dir="rtl">• להציג אישור שמירה מוצלחת ולמנוע שליחה כפולה.</span>
>
> <span dir="rtl">• לאחר שמירה מוצלחת, להציג את מסך אישור הסיום הקיים עם כפתור "חזרה להיום". אין מעבר אוטומטי למסך הבית.</span>
>
> <span dir="rtl">• במצב אופליין, להבחין בין שמירה מקומית הממתינה לסנכרון לבין שמירה שהגיעה לשרת.</span>

# <span dir="rtl">פרק 2 — ממשק שירות הלקוחות (שיראל)</span>

<span dir="rtl">התיקונים שלהלן מבוססים על מסמך ההערות, צילומי המסך שהועברו והחלטות שאושרו. חלק מהנושאים הם דרישות לפיתוח או לבדיקה — לא באגים שהוכחו במערכת הפעילה.</span>

## <span dir="rtl">1. הסרת מסך הבית</span>

<span dir="rtl">• להסיר מממשק שירות הלקוחות את מסך "בית" ואת הקישור אליו בניווט. מסך זה אינו נחוץ לתהליכי העבודה של שיראל.</span>

<span dir="rtl">• להציג כברירת מחדל מסך קריאות.</span>

## <span dir="rtl">2. סנכרון מצב הביקורים ביומן הטכנאים</span>

<span dir="rtl">• שינוי סטטוס המבוצע על ידי הטכנאי יתעדכן גם ביומן הטכנאים של שירות הלקוחות ללא הזנה כפולה.</span>

<span dir="rtl">• כל כרטיס ביקור ביומן יציג את סטטוס הביקור העדכני במילים ובצבע התואם לסטטוס.</span>

<span dir="rtl">• להציג בכרטיס הביקור ביומן גם את מספר הפנייה המקושר ב־ONE, באופן קריא כבר בתצוגת היומן, בלי צורך לפתוח כרטיס.</span>

<span dir="rtl">• לוודא הצגה עקבית של מצב הביקור בתצוגה היומית, השבועית והחודשית.</span>

## <span dir="rtl">3. עדכון קריאות וכרטיסי קריאה</span>

<span dir="rtl">• שינויי סטטוס מהשטח יתבטאו במסך "קריאות" ובכרטיס הקריאה הרלוונטי.</span>

<span dir="rtl">• בכרטיס הקריאה להציג חתימת לקוח כאשר קיימת, לצד סיכום הטיפול והתיעוד שהמשתמש מורשה לראות.</span>

<span dir="rtl">• להבחין בין סטטוס הקריאה הכולל (למשל פתוחה / טופלה / ממתינה לשיבוץ) לבין סטטוס הביקור (למשל שובצה / בדרך / בטיפול / המשך טיפול).</span>

<span dir="rtl">• ביקור שסומן "המשך טיפול" ייחשב ביקור שהושלם, אך הקריאה תישאר פתוחה עד טיפול המשך או סגירה.</span>

## <span dir="rtl">4. הסרת מסכים שאינם נדרשים</span>

<span dir="rtl">• להסיר מהניווט הראשי של שירות הלקוחות את המסכים "לקוחות" ו"חזרו מהשטח".</span>

<span dir="rtl">• המשך עבודה בעקבות ביקור שלא טופל יתנהל ב־ONE; אין צורך במסך עצמאי של "חזרו מהשטח".</span>

<span dir="rtl">• למרות הסרת מסך "לקוחות", לשמור גישה לפרטי לקוח הנחוצים לצורך טיפול בקריאה דרך כרטיס הקריאה ובהתאם להרשאות. אין להסיק מכך שיש למחוק נתונים או את התשתית שמאחורי המסכים.</span>

## <span dir="rtl">5. ניווט מרכזי ממוקד</span>

<span dir="rtl">• הניווט המרכזי לשירות הלקוחות יכלול: "יומן טכנאים", "קריאות" ו"זימונים שלא נקלטו".</span>

<span dir="rtl">• לשמור את מסך "זימונים שלא נקלטו", ובו פירוט ברור של הסיבה לכישלון קליטת הזימון והמידע הדרוש לתיקונו.</span>

<span dir="rtl">• כל גישה למידע או לפעולה שהייתה במסכים שהוסרו תישמר דרך מסך רלוונטי, אם היא עדיין נדרשת לעבודה והמשתמש מורשה לכך.</span>

## <span dir="rtl">6. סנכרון בין הטכנאי לשירות הלקוחות</span>

<span dir="rtl">• לאחר סיום ביקור, שיראל תראה במערכת את תוצאת הביקור, מועד הסיום והמסמכים הנלווים בהתאם להרשאות.</span>

<span dir="rtl">• הנתונים יתעדכנו מתוך אותו מקור מידע משותף, ולא באמצעות עדכון ידני מקביל של כל מסך.</span>

<span dir="rtl">• הקשר בין קריאת שירות לביקורי המשך יישמר, כולל היסטוריית הביקורים והסטטוסים.</span>

# <span dir="rtl">7. שיפור, עיצוב וסידור כרטיסיית קריאה.</span>

<span dir="rtl">יש לשפר את המבנה והעיצוב של כרטיס הקריאה, כך שהמידע יוצג בצורה מסודרת, ברורה ונוחה לקריאה, בהתאם לדמו המעודכן שאישרנו.</span>

1.  <span dir="rtl">שינוי סדר הכרטיסיות:</span>

- <span dir="rtl">בראש המסך יוצגו פרטי הלקוח, מספר הפנייה וסטטוס הקריאה</span>.

- <span dir="rtl">מתחת יוצגו שתי כרטיסיות</span>: **"<span dir="rtl">פרטי הקריאה" בצד ימין</span>** <span dir="rtl">ו\*\*"לקוח וכתובת" בצד שמאל</span>\*\*.

- <span dir="rtl">בהמשך יוצגו כרטיסיית "שיבוץ" וכרטיסיות הביקורים שבוצעו</span>.

- <span dir="rtl">לשמור על עיצוב</span> RTL <span dir="rtl">והתאמה למחשב, לטאבלט ולטלפון</span>.

2.  <span dir="rtl">כרטיסיית פרטי קריאה:</span>

- <span dir="rtl">להציג את מספר הקריאה בראש הכרטיסייה בצורה בולטת</span>.

- <span dir="rtl">להציג את סוג הקריאה, המוצר, המק"ט, המותג/ספק, האחריות ותיאור התקלה</span>.

- <span dir="rtl">לסדר את הנתונים במבנה אחיד של שם שדה וערך</span>.

3.  <span dir="rtl">כרטיסיית שיבוץ:</span>

- <span dir="rtl">להציג את שם הטכנאי המשובץ</span>.

- <span dir="rtl">להציג את תאריך הביקור</span>.

- <span dir="rtl">להציג את שעות השיבוץ המתוכננות, לדוגמה: 09:00–11:00</span>.

- <span dir="rtl">להציג את סטטוס הביקור</span>.

- <span dir="rtl">לשמור על הפרדה בין שעות השיבוץ המתוכננות לבין זמני הביצוע בפועל</span>

4.  <span dir="rtl">כרטיסיית "פרטי ביקור"</span>.<span dir="rtl">:</span>

<span dir="rtl">יש להציג לכל ביקור את הנתונים הבאים</span>:

- <span dir="rtl">מספר ביקור</span>: <span dir="rtl">מספר הביקור במסגרת הקריאה</span>.

- <span dir="rtl">תאריך</span>: <span dir="rtl">תאריך ביצוע הביקור</span>.

- <span dir="rtl">שעת יציאה</span>: <span dir="rtl">מועד יציאת הטכנאי לקריאה</span>.

- <span dir="rtl">שעת הגעה</span>: <span dir="rtl">מועד הגעת הטכנאי ללקוח</span>.

- <span dir="rtl">שעת סיום</span>: <span dir="rtl">מועד סיום הטיפול</span>.

- <span dir="rtl">טווח כולל</span>: <span dir="rtl">משעת היציאה ועד שעת סיום הטיפול, כולל הנסיעה</span>.

- <span dir="rtl">משך טיפול כולל</span>: <span dir="rtl">הזמן שעבר משעת היציאה ועד לסיום הטיפול</span>.

- <span dir="rtl">משך טיפול</span>: <span dir="rtl">הזמן שעבר משעת ההגעה ועד לסיום הטיפול, ללא הנסיעה</span>.

- <span dir="rtl">זמן נסיעה</span>: <span dir="rtl">הזמן שעבר משעת היציאה ועד ההגעה ללקוח</span>.

<span dir="rtl">הנתונים יחושבו אוטומטית על בסיס הזמנים שנרשמו במערכת</span>.

5.  <span dir="rtl">סיכום ותיעוד הביקור:</span>

<span dir="rtl">מתחת לנתוני הזמנים יוצגו:</span>

- <span dir="rtl">סיכום הטיפול שביצע הטכנאי.</span>

- <span dir="rtl">חלפים שהוחלפו במהלך הביקור.</span>

- <span dir="rtl">תמונות וסרטונים.</span>

- <span dir="rtl">הקלטה או סיכום מתומלל, אם קיימים.</span>

- <span dir="rtl">חתימת הלקוח, אם קיימת.</span>

- <span dir="rtl">במקרה של המשך טיפול – הסיבה ופירוט הפעולות הנדרשות.</span>

<span dir="rtl">כאשר קיימים מספר ביקורים לאותה קריאה, כל ביקור יוצג בנפרד תוך שמירה על היסטוריית הטיפולים.</span>

6.  <span dir="rtl">שיפור הנראות הכללית:</span>

- <span dir="rtl">להציג את המידע בכרטיסיות ברורות עם כותרות מודגשות.</span>

- <span dir="rtl">לשמור על יישור אחיד וריווח קבוע בין הנתונים.</span>

- <span dir="rtl">לצמצם שטחים ריקים שאינם נחוצים.</span>

- <span dir="rtl">להדגיש סטטוסים באמצעות צבעים אחידים.</span>

- <span dir="rtl">לשמור על העיצוב הקיים של</span> MODY<span dir="rtl">.</span>

- <span dir="rtl">אין לשנות את הלוגיקה העסקית, נתוני הקריאה או הרשאות המשתמשים במסגרת שינוי העיצוב.</span>

# <span dir="rtl">פרק 3 — ממשק המנהל (רותם)</span>

## <span dir="rtl">1. דשבורד — ביקורים שלא בוצעו במועד</span>

<span dir="rtl">• בלחיצה על המדד "לא בוצעו במועד", להציג את רשימת הביקורים הרלוונטיים.</span>

<span dir="rtl">• לכל ביקור להציג את השעות המתוכננות לשיבוץ ואת שעת ההגעה בפועל, אם קיימת.</span>

<span dir="rtl">• כשלא בוצעה הגעה, להציג במפורש "לא הגיע" או "טרם הגיע", בהתאם למצב הביקור.</span>

<span dir="rtl">• לאפשר כניסה מכרטיס הביקור לפרטי הקריאה, לפי הרשאות המנהל.</span>

## <span dir="rtl">2. ניסוח ושמות מדדי השירות</span>

<span dir="rtl">• "זמן טיפול ממוצע" - "ממוצע זמן טיפול".</span>

<span dir="rtl">• "זמן נסיעה ממוצע" - "ממוצע זמן נסיעה".</span>

<span dir="rtl">• "זמן סגירת קריאה" - "ממוצע זמן סגירת קריאה".</span>

<span dir="rtl">• "פתרון בביקור ראשון" - "אחוז התקלות שנפתרו בביקור הראשון".</span>

<span dir="rtl">• להציג ליד כל מדד את יחידות המדידה ואת התקופה שאליה הוא מתייחס.</span>

## <span dir="rtl">3. מדד עמידה בתכנון</span>

<span dir="rtl">• בממשק הנוכחי מופיע עבור מדד "עמידה בתכנון" הנוסח "הגדרה ממתינה" אפשר למחוק את זה.</span>

## <span dir="rtl">4. יומן טכנאים — סטטוסים ומספרי פניות</span>

<span dir="rtl">• שינוי סטטוס ביקור בממשק הטכנאי ישתקף גם ביומן המנהל ובכרטיס הקריאה.</span>

<span dir="rtl">• בכל ביקור ביומן יוצגו סטטוס מילולי וצבע עקבי, וכן מספר הפנייה המשויך ב־ONE, ללא צורך בפתיחת הכרטיס.</span>

<span dir="rtl">• לוודא שהמידע עדכני ועקבי בתצוגות יום, שבוע וחודש; סנכרון בפועל מחייב בדיקה תפקודית ולא ניתן לאמתו מצילומים בלבד.</span>

## <span dir="rtl">5. קריאות — חתימות ותיעוד</span>

<span dir="rtl">• בכרטיס הקריאה להציג את חתימת הלקוח כאשר קיימת חתימה, לצד התיעוד וסיכום הטיפול.</span>

<span dir="rtl">• לשמור רצף ביקורים מלא עבור אותה קריאה, לרבות תוצאות ביקורי המשך, ללא יצירת קריאה כפולה.</span>

<span dir="rtl">• כרטיסיית ביקור שתהיה תואמת לעיצוב החדש לפי ההגדרות שהעלו אצל השינויים אצל שיראל</span>

## <span dir="rtl">6. ניהול משתמשים — הרשאות מנהל לעומת יוצר</span>

<span dir="rtl">• המנהל רשאי להוסיף משתמש מסוג "טכנאי" או "שירות לקוחות" דרך כפתור הוספה אחד, עם בחירת תפקיד במהלך יצירת המשתמש.</span>

<span dir="rtl">• המנהל רשאי לערוך פרטי משתמש ולשנות "סטטוס פעילות" בין "פעיל" ל"לא פעיל".</span>

<span dir="rtl">• משתמש שסטטוס הפעילות שלו "לא פעיל" לא יוכל להתחבר לאפליקציה, תוך שמירה על נתוניו והיסטוריית הביקורים והפעולות שלו.</span>

<span dir="rtl">• למנהל לא תוצג ולא תינתן אפשרות למחיקת משתמש.</span>

<span dir="rtl">• רק ליוצר (Creator) תהיה בנוסף אפשרות למחוק משתמש מהמערכת, לאחר אישור מחיקה מפורש ובהתאם למדיניות שמירת נתוני העבר.</span>

<span dir="rtl">• אין לפרש הרשאות אלה כמתן גישה גורפת למנהל לכל הגדרות המערכת; יש להקצות הרשאות מוגדרות לפעולות שאושרו.</span>

## <span dir="rtl">7. הגדרות תפעוליות למנהל</span>

<span dir="rtl">דרישה מאושרת — בממשק רותם (מנהל) תופיע בתפריט הראשי לשונית אחת בלבד בשם ״הגדרות״. בתוך לשונית זו יהיו ארבעה אזורי ניהול פנימיים: (1) משתמשים והרשאות; (2) סיבות המשך טיפול; (3) נוסח אישור ״טופל״; (4) סוגי קריאה. אין להוסיף לתפריט הראשי לשוניות נפרדות כגון ״הגדרות משתמשים״ או ״הגדרות טיפול וקריאות״.</span>

- סיבות המשך טיפול <span dir="rtl"></span>הצגת רשימת הסיבות הקיימות; הוספת סיבה חדשה; הפעלה/השבתה של סיבה. שינוי ישפיע על האפשרויות הזמינות לטכנאי בסיום ביקור. סיבה שכבר קיימת בהיסטוריית ביקורים לא תימחק באופן שיפגע בנתונים

  - נוסח אישור ״טופל״: הצגת הטקסט הנוכחי ועריכתו, עם כפתור ״שמירה״. הנוסח המעודכן יופיע בשלב חתימת הלקוח לאחר בחירת ״טופל״; אישורים קודמים ישמרו את הטקסט שעליו נחתם בפועל

  - סוגי קריאה: הצגת הסוגים הקיימים, הוספת סוג חדש, והפעלה/השבתה של סוג. שינוי ישפיע על אפשרויות הבחירה הרלוונטיות וישמור את הסיווג בקריאות היסטוריות

<span dir="rtl">• גבול הרשאה: ארבעת אזורי ההגדרות יוצגו תחת לשונית ״הגדרות״ אחת; המנהל יוכל להוסיף, לערוך ולהפעיל/להשבית משתמשים אך לא למחוק. הגדרות אחרות המיועדות ליוצר בלבד לא ייפתחו למנהל.</span>

- בדיקת קבלה: להתחבר כמנהל, לוודא שבתפריט הראשי קיימת לשונית ״הגדרות״ אחת בלבד, לעבור בין ארבעת האזורים הפנימיים, לשמור שינוי בכל אחד משלושת סוגי ההגדרות, ולוודא שהנתונים נשמרים ונאכפים גם בצד השרת. ודאו שלא מוצגת למנהל אפשרות מחיקת משתמש.

<span dir="rtl">• בתוך ״הגדרות״ יוצגו למנהל: משתמשים והרשאות, סיבות המשך טיפול, נוסח אישור ״טופל״ וסוגי קריאה — ללא כפילות בניווט הראשי.</span>

<span dir="rtl">• לשמור את ההבחנה בין הגדרות תפעוליות אלה לבין הגדרות מערכת המיועדות ליוצר בלבד.</span>

<span dir="rtl">• כל שינוי בהגדרות ישתקף בממשקי המשתמשים הרלוונטיים באופן עקבי, בכפוף להרשאות.</span>

## <span dir="rtl">8. שמירה על העיצוב והמבנה הקיים</span>

<span dir="rtl">• לשמר את שלוש לשוניות הדשבורד: "כללי", "טכנאים", "מוצרים וספקים".</span>

<span dir="rtl">• לשמר מסנני תקופה ופילוח טכנאים כפי שהוגדרו; להציג באופן ברור את תקופת המדידה בכל לשונית.</span>

<span dir="rtl">• לשמר את מסכי "קריאות" ו"זימונים שלא נקלטו" ואת יכולת הייצוא ל־Excel בהתאם להרשאות.</span>

<span dir="rtl">• שינויים חזותיים יתמקדו בקריאות הנתונים, צפיפות המידע ועקביות סטטוסים — ללא עיצוב מחדש של הדשבורד.</span>

## <span dir="rtl">9. הסרת פס "התקדמות הביקורים" מהדשבורד הכללי</span>

<span dir="rtl">• להסיר לחלוטין מהדשבורד את פס ההתקדמות האופקי, את האחוז ואת מקרא חלוקת הסטטוסים הנלווים אליו.</span>

<span dir="rtl">• להשאיר את כרטיסי הפעילות היומית: מתוכננים, בוצעו, נותרו ולא בוצעו במועד.</span>

<span dir="rtl">• לאחר ההסרה, לצמצם את החלל הריק כך שהמדדים והאזור הבא יופיעו גבוה יותר.</span>

<span dir="rtl">• ההסרה חלה על הדשבורד הכללי של מנהל ויוצר, ללא שינוי במדדי השירות או בשאר לשוניות הדשבורד.</span>

## <span dir="rtl">בדיקות נדרשות לפני העברה לפיתוח</span>

<span dir="rtl">• לוודא שהבחירה במדד "לא בוצעו במועד" פותחת פירוט מדויק של זמני שיבוץ והגעה.</span>

<span dir="rtl">• לוודא שעדכון סטטוס של טכנאי משתקף ביומן המנהל, בכרטיס הקריאה ובמדדי הדשבורד.</span>

<span dir="rtl">• לבדוק הצגת חתימת לקוח רק בקריאות שבהן חתימה קיימת בפועל.</span>

<span dir="rtl">• לבדוק שהשבתת משתמש מונעת התחברות ואינה מוחקת את היסטוריית הנתונים.</span>

<span dir="rtl">• לבדוק שמחיקת משתמש נגישה ליוצר בלבד, בצד השרת ולא רק בהסתרת כפתור.</span>

<span dir="rtl">• לקבוע את הגדרת מדד "עמידה בתכנון" לפני מימושו.</span>

## <span dir="rtl">החלטה שאושרה — סטטוס פעילות ומחיקת משתמשים</span>

<span dir="rtl">רותם (מנהל): הוספה, עריכה והפעלה/השבתה של משתמשים; ללא מחיקה. יוצר: אותן יכולות, ובנוסף אפשרות למחיקת משתמש לאחר אישור. היסטוריית פעולות וביקורים תישמר בהתאם למדיניות שמירת הנתונים.</span>

## <span dir="rtl">פרק 4 — ממשק היוצר (Creator)</span>

<span dir="rtl">הפרק מבוסס על צילומי מסכי היוצר, הדמו המקורי והחלטות המשתמש שאושרו. תכונות מדידה מתקדמות מתוארות כדרישות ולא כיכולות שנבדקו בפועל.</span>

## <span dir="rtl">1. ניהול משתמשים מאוחד</span>

<span dir="rtl">• לרכז באותו מסך ניהול את המשתמשים מכל התפקידים: טכנאי, שירות לקוחות, מנהל ויוצר.</span>

<span dir="rtl">• להסיר כפילות ניהולית בין "משתמשים והרשאות" ל"טכנאים"; לא למחוק נתוני טכנאים או פרטים ייעודיים.</span>

<span dir="rtl">• להציג כפתור אחד "הוסף משתמש"; תפקיד המשתמש ייבחר בטופס ההוספה.</span>

<span dir="rtl">• בעריכת טכנאי יוצגו גם הגדרות ייעודיות: מספר טלפון, דוא״ל Outlook, צבע ביומן ומעמד הפעילות.</span>

<span dir="rtl">• לכל משתמש: עריכה, הפעלה/השבתה; ליוצר בלבד גם מחיקה מפורשת לאחר אישור.</span>

<span dir="rtl">• בהשבתה תיחסם התחברות, תוך שמירת היסטוריית הביקורים והפעולות; במחיקה יש לשמר קשרים היסטוריים בהתאם למדיניות שמירה שתאושר.</span>

<span dir="rtl">• לשמור את מטריצת ההרשאות. שינוי תפקיד או מצב פעילות אינו מעניק הרשאות שלא הוגדרו.</span>

## <span dir="rtl">2. הסרת אזור "בקשות לאישור"</span>

<span dir="rtl">• להסיר מהגדרות היוצר את אזור בקשות האישור, הרשימה וכפתורי אישור/דחייה השייכים אליו.</span>

<span dir="rtl">• אין להסיר את מנגנוני אימות המשתמשים, הרשאות השרת או הבקרות האבטחתיות בגלל הסרת רכיב הממשק.</span>

<span dir="rtl">• להותיר ניהול משתמשים, הרשאות ומדיניות פעילות החשבונות במסך המאוחד.</span>

## <span dir="rtl">3. דשבורד "מדדי שימוש" בתפריט הראשי</span>

<span dir="rtl">• להוסיף בתפריט הראשי לשונית נפרדת בשם "מדדי שימוש", הזמינה ליוצר בלבד.</span>

<span dir="rtl">• לבסס נתונים על אירועי שימוש אמיתיים והגדרות KPI מתועדות; לא להציג ספירות לחיצה מדומות כנתוני אמת.</span>

<span dir="rtl">• להציג מסנני יום / שבוע / חודש / טווח מותאם, ולציין על כל מדד את התקופה הרלוונטית.</span>

<span dir="rtl">• לאפשר פילוח לפי תפקיד ולפי עובד מורשה; להימנע מחשיפת תוכן לקוחות, הקלטות וחתימות בנתוני אנליטיקה.</span>

## <span dir="rtl">4. מדדי שימוש ואימוץ</span>

<span dir="rtl">• כמות משתמשים פעילים ביום, בשבוע ובחודש ואחוז שימוש מתוך המשתמשים המורשים הפעילים.</span>

<span dir="rtl">• כמות כניסות, ימים פעילים, כניסה אחרונה וזמן שימוש במערכת לפי משתמש.</span>

<span dir="rtl">• מספר ביקורים שתועדו ונסגרו דרך האפליקציה, וכן שיעור השלמת התהליך.</span>

<span dir="rtl">• שימוש לפי תפקיד: טכנאי / שירות לקוחות / מנהל / יוצר.</span>

## <span dir="rtl">5. מדדי מסכים, כפתורים ותהליכים</span>

<span dir="rtl">• מסכים עם הכי הרבה צפיות וכפתורים עם הכי הרבה לחיצות.</span>

<span dir="rtl">• כמות לחיצות על כל פעולה מרכזית ומספר משתמשים ייחודיים שהפעילו אותה.</span>

<span dir="rtl">• פונקציות שלא הופעלו בתקופה שנבחרה.</span>

<span dir="rtl">• פתיחות של פרטי קריאה, כניסות לדשבורד ושימוש ב-Waze.</span>

<span dir="rtl">• השלמת תהליך ביקור מהפעלת ניווט ועד לתוצאה "טופל" או "המשך טיפול"; להבחין בין ניסיון להפעלה מוצלחת.</span>

<span dir="rtl">• פילוח תיעוד ביקורים: סיכום כתוב לעומת הקלטה, שימוש בתמונות ובחתימות.</span>

## <span dir="rtl">6. מדדי יציבות וביצועים</span>

<span dir="rtl">• כמות שגיאות אפליקציה ושיעור פעולות שנכשלו.</span>

<span dir="rtl">• זמן טעינה ממוצע של מסכים ואחוז טעינות איטיות, בכפוף להגדרה שתאושר.</span>

<span dir="rtl">• כמות כישלונות התחברות.</span>

<span dir="rtl">• כמות סנכרונים שנכשלו, פריטים ממתינים ואחוז סנכרונים שהצליחו; ללא איסוף תוכן רגיש.</span>

## <span dir="rtl">7. שמירת ההגדרות התפעוליות</span>

<span dir="rtl">• לשמר מקומות איסוף, סיבות המשך טיפול, סוגי קריאה, מיילים והתראות ותבנית זימון.</span>

<span dir="rtl">• בהגדרות מיילים לסמן תכונות הממתינות לחיבור Microsoft 365; אין להציג הודעות כהודעות שנשלחו בפועל בטרם חיבור.</span>

<span dir="rtl">• לשמור את ההבחנה בין הגדרות תפעוליות נגישות למנהל בהרשאות מפורשות לבין הגדרות מערכת המיועדות ליוצר בלבד.</span>

<span dir="rtl">• להסיר גם בדשבורד הכללי של היוצר את פס "התקדמות הביקורים" בהתאם להחלטה שאושרה בממשק המנהל.</span>

## <span dir="rtl">נקודות אימות לפני פיתוח</span>

<span dir="rtl">• לבדוק האם כבר קיימת תשתית טלמטריה כלשהי; במסכים שנשלחו לא ניתן לאמת שיש איסוף אירועים אמיתי.</span>

<span dir="rtl">• לקבוע מאפייני פרטיות, הרשאות צפייה ותקופות שמירת מידע לאנליטיקה.</span>

<span dir="rtl">• לוודא שפעולות מחיקה והשבתה נאכפות בצד השרת ולא רק בהסתרת כפתורים.</span>

<span dir="rtl">• לבדוק מה מבין פעולות ההגדרות מתפקד בדמו ומה תלוי עדיין בהשלמת backend ובחיבורי צד שלישי.</span>

## <span dir="rtl">החלטות סופיות שאושרו בפרק היוצר</span>

<span dir="rtl">• אין צורך ברכיב "בקשות לאישור" בהגדרות היוצר.</span>

<span dir="rtl">• "מדדי שימוש" הוא מסך ראשי עצמאי ליוצר בלבד.</span>

<span dir="rtl">• למנהל אין אפשרות מחיקה; ליוצר בלבד קיימת מחיקה, לצד הפעלה והשבתה.</span>

<span dir="rtl">• יש לאחד את ניהול הטכנאים והמשתמשים בלי לבטל הגדרות ייעודיות לטכנאים.</span>

<span dir="rtl">הערה: מסכי הדמו הנלווים הם המחשה חזותית ואינטראקטיבית לתכנון, עם נתונים פיקטיביים. הם אינם קוד ייצור ואינם הוכחה לתפקוד אינטגרציות.</span>
